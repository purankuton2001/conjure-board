# CLAUDE.md

Working rules for Conjure Board. They apply to AI coding agents (Claude Code, Codex and others; `AGENTS.md` points here) and to humans, whether you are editing this repository directly or working in the ops repository that generates it.

## This repository is public and generated

Everything here is visible to anyone, forever: files, commit messages, author names and emails. The site is served from `main` by GitHub Pages. Content is rendered and pushed by the maintainers' private ops repository; pull requests here are not merged. That makes the publisher the last line of defence: whatever it pushes is published.

History in the sibling app repositories was rewritten once (2026-09-07) to remove a personal email, private project names and tool session links. The rules below exist so that never has to happen here. `scripts/check-public-hygiene.sh` enforces them and runs in CI on every push (`.github/workflows/hygiene.yml`). The publisher should run the same script on its output before pushing.

### Commits

- Author and committer email must be a GitHub noreply address (`<id>+<login>@users.noreply.github.com`) or a tool's noreply address. Never a personal mailbox.
- The message describes the change. The only allowed trailer is `Co-Authored-By`. No session links, run IDs or other tracking trailers, even if your tooling asks for one.
- Do not reference file paths or tooling inside the ops repository. The blocked list lives in `scripts/check-public-hygiene.sh`; extend it when a new private name or path appears.

### Files

- Describe processes, not private files. "Generated by the maintainers' tooling" is fine; a path into the ops repository, or an `npm run` command that does not exist here, is not.
- Stream reports are public documents. They carry what the streamer posted publicly (stream URL, persona name, clip, metrics) and never an email address, a session log or an API key. Session logs are read from the issue and discarded; the issue template tells reporters to strip keys first.
- Spec documents under `data/spec/` are published on purpose. Before publishing a new version, remove TODOs about unverified trademarks, domains or handles, and links to files that are not in this repository.
- Assets need a licence that permits redistribution (`assets/lobe-icons-LICENSE` is the model) and must be original or generated; no real people, no existing characters.
- No secrets of any kind. There is no `.env` here and there never will be.

### Checking

```bash
bash scripts/check-public-hygiene.sh
```

The check scans every commit after a fixed baseline and every tracked file. If it fails after a publish, fix the generator in the ops repository and publish again; do not hand-edit here, the next publish would undo it.

Known case: the publish of 2026-09-07 overwrote three files that had been fixed by hand (`.github/ISSUE_TEMPLATE/stream-report.yml` lost its public-repository warning, `data/reports/README.md` regained ops-only `npm run` instructions, `data/spec/REQUIREMENTS-v0.8.md` regained a dangling link and a trademark to-do). The check now blocks those strings, so the next publish fails until the generator's templates carry the fixed versions. The fixed versions are the ones in this repository at the commit that added this file.

## Repository shape

- `index.html`, `gallery.html`, `versus.html`, `report.html`, `weekly.html`: the static site (no build step). `assets/style.css`, `assets/language.js` (five-language switch, stores the choice in `localStorage`).
- `board.json`: the Board as data. `data/reports/*.json`: accepted stream reports (`_example.json`, `schema.json` describe the shape). `data/tiers.json`, `data/versus.json`, `data/apps.json`: tiers, comparison table, app summaries.
- `data/spec/REQUIREMENTS-v0.8.md`: the requirements document both apps were built from (Japanese). `data/ip-names.txt`: shared exclusion list.
- `.github/ISSUE_TEMPLATE/`: stream report and takedown forms; the report form is the only input channel.
